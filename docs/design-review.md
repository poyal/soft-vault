# 디자인과 실제 창 검수

## 기준의 우선순위

최신 사용자 지정 → [계획서](../plan.md)의 확정 요구사항 → [실제 공통 스타일](../lib/design.dart)·[원본 시안](../design/review.html) 순서로 차이를 해석한다. 시안이 오래됐다는 이유로 최근에 요청한 기능을 되돌리지 않는다.

Soft Vault는 Side Deck + Quiet Folder를 사용한다. 영상 전용 목록, 재생 상단 표시줄 제거, 상세정보 보기, 배우·태그 전체 항목, 목록의 배우·태그 표시, 하단 바 제거, 상단 설정 버튼, 통합 설정과 사생활 보호는 의도된 변경이다.

## 공통 스타일

| 역할 | 현재 값 |
| --- | --- |
| 앱 배경 | `#15191E` |
| 사이드바 | `#1C2229` |
| 표면·구분선 | `#242C35` / `#323D49` |
| 본문·보조 글자 | `#E3EAF1` / `#8A9BAA` |
| 강조·평점 | `#87B8D8` / `#BDAF8C` |
| 기본 글꼴 | Segoe UI, 플랫폼·한글 대체 글꼴은 `main.dart` 확인 |

색·글꼴·SVG가 같다는 사실만으로 화면 합격을 선언하지 않는다. 버튼 위치·행 높이·여백·긴 문구·입력과 오류 상태를 실제 렌더링으로 확인한다. 폰트 파일 번들 여부와 플랫폼 대체 글꼴 차이도 기록한다.

## 필수 화면과 상태

| 범위 | 확인할 상태 |
| --- | --- |
| 라이브러리 | 목록·그리드·빈 목록·검색 없음·오프라인·단일 선택·카드/우클릭 메뉴 |
| 영상 | 비율 유지·조작부·사이드 목록·전체화면·최소화/복원 |
| 정보·분류 | 상세 읽기/편집, 긴 배우·태그, 전체 항목, 평점 |
| 정리 | 장면·썸네일·컬렉션·중복·이동 규칙·진행/실패 |
| 설정 | 라이브러리·재생·단축키·사생활 보호·백업 |
| 잠금 | 첫 설정·잘못된 비밀번호·재시도 대기·손상 정보·잠금 해제 |

1280×800·1440×900은 **앱 내부 화면** 기준이다. 별도로 작은 실제 창, 최대화, 전체화면, 복원도 확인한다. 좁은 창·긴 한글·빈 메타데이터·키보드 포커스·스크롤 하단의 버튼까지 접근할 수 있어야 한다.

## 레터박스와 캡처

영상 종횡비로 생기는 여백은 영상 영역 안에서 허용한다. 앱 전체와 사이드바 바깥에 비율 맞춤 검은 띠가 생기는 것은 결함으로 다룬다.

[native_surface.dart](../integration_test/support/native_surface.dart)는 실제 창의 제목 표시줄·테두리와 내부 크기 차이를 계산한다. 테스트에 가짜 `physicalSize`, DPI, `setSurfaceSize`를 넣어 실제 Windows 창에 가상 캔버스를 축소하지 않는다. 논리 크기·물리 크기·DPI·추가 축소/이동 없는 변환을 확인한다. 전체화면은 실제 디스플레이 해상도로 기록한다.

## 비교 절차

1. 고정된 합성 콘텐츠와 현재 UI 코드로 디자인 E2E를 실행한다. 실제 사용자 이름·경로·비밀번호는 촬영하지 않는다.
2. [build-review.ps1](../scripts/build-review.ps1)로 대조 HTML을, [compare-design.ps1](../scripts/compare-design.ps1)로 픽셀 측정을 만든다.
3. 같은 화면·크기·콘텐츠끼리 배치와 상태를 눈으로 검토한다. 자동 검사와 시각 검토 결과를 구분한다.
4. 차이를 결함 / 의도된 변경 / 렌더러·글꼴 차이 / 미확인으로 분류하고 근거를 남긴다.
5. 수정한 화면을 다시 캡처한다. 기준 이미지를 현재 실패 화면으로 자동 교체해서 검사를 통과시키지 않는다.

RGB 평균 오차와 픽셀 일치율에는 배경 비중·문자 안티앨리어싱이 포함된다. 이 수치만으로 디자인 완성도나 100% 일치를 주장하지 않는다. HDR 색 정확도는 SDR 캡처의 픽셀 비교로 판정하지 않는다.
