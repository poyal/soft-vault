# 파일 목록·재생 컨트롤 UI 시나리오 감사

2026-11-13, 기준 HEAD `6d640da` 이후 작업 트리의 UI 변경을 Windows에서 검사했다. 시험 영상과 임시 SQLite DB를 사용했으며 사용자 라이브러리와 원본 파일은 시험 대상으로 사용하지 않았다.

## 발견 및 수정

1. 재생 화면에서 활성 필터 표시와 ‘필터 해제’가 사라졌다. 재생 여부와 관계없이 활성 필터를 표시하고, 필터가 없을 때는 빈 공간을 만들지 않도록 수정했다. 실제 Windows 시험에서 실패를 재현한 뒤 통과했다.
2. 정렬 팝업을 열면 `CheckedPopupMenuItem` 내부 ListTile의 배경과 ink 관련 Flutter 렌더링 경고가 발생했다. 체크 아이콘과 선택 접근성 정보를 가진 일반 PopupMenuItem으로 교체했다.
3. A를 재생하면서 B를 선택하면 재생바 별점 클릭은 A에, 숫자 단축키는 B에 적용됐다. 재생 중 별점 입력과 초기화는 모두 재생 파일에 적용하도록 통일했다. 재생 대기 상태에서는 선택 파일을 대상으로 한다.

기존 카탈로그 시험의 제거된 메서드 호출과 라이브러리 시험의 자기 자신과 비교하는 검증도 수정했다. README와 E2E 문서에 남아 있던 다중 선택·옛 컨텍스트 메뉴 설명을 현재 동작에 맞췄다.

## 보강한 시나리오

- 우클릭과 더보기 메뉴의 대상 파일이 목록 선택과 다를 때에도 정확한 파일의 상세정보를 연다. 제거된 메뉴와 ‘전체 선택’ 설정이 남지 않는다.
- 상세정보에서 표시 제목·배우·태그를 편집하고 취소하거나 저장한다. 표시 제목 변경은 원본 파일명을 바꾸지 않는다.
- 상세정보의 이름 변경을 취소하면 원본을 유지한다. 실행하면 파일 ID와 메타데이터를 유지하며 해당 파일만 이동한다.
- 재생 파일과 선택 파일이 다를 때 숫자 평점과 Shift+0 초기화가 재생 파일에 적용된다.
- 평점 변경으로 파일이 필터 결과에서 사라져도 재생바 평점이 유지되고 필터를 해제할 수 있다.
- 임시 DB 트리거로 평점 저장 실패를 주입하면 이전 평점을 유지하고 오류를 표시한다.
- 별점 저장 직후 다른 영상을 열어도 서로 다른 파일의 평점을 덮어쓰지 않는다.
- 화면을 해제하고 DB를 닫았다 다시 열어 새 앱 위젯을 구성해도 저장된 평점을 복원한다. OS 프로세스를 종료하고 재실행하는 시험과는 구분한다.
- 카드 폭 310·400·520 및 글자 배율 100·150%에서 배우·태그의 왼쪽, 시간·별점의 오른쪽 정렬을 검사한다. 별점 클릭 영역 가장자리도 검사한다.

## 남은 검증 범위

- macOS 실기와 macOS 전용 폴더 별칭 검사, load/stress 대용량 검사는 이번 감사에서 실행하지 않았다.
- Windows 설치 패키지 생성·업데이트 설치·공개 배포 검사는 수행하지 않았다.
- DB 재열기 검사는 같은 시험 프로세스에서 수행했다. OS 프로세스 강제 종료 중 저장 복구는 별도 검증 대상이다.

현재 UI 변경에는 새 기능을 더하기보다 이번 회귀 시나리오를 유지하는 것이 우선이다. 다음 배포 전에는 설치본 재실행과 대규모 라이브러리에서 필터·정렬 응답성을 추가로 확인할 수 있다.
