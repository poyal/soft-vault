# 폴더 등록 지연 수정과 Falcon 관리 메뉴 검토

기준 소스: `07f69eb8852a144cdb8d9b642b0afcfd1b1499e7`, 로컬 브랜치 `fix/folder-scan-loading`. Windows 설치본 0.2.0의 문제를 조사했다. 개인 파일명·경로·영상은 이 기록에 포함하지 않는다.

## 원인과 변경

- 연결 대상은 영상 174개, 약 632GiB였다. 기존 프로세스는 약 272MB/s로 파일을 읽는 동안 화면·DB에 항목이 0개였다.
- 첫 스캔이 모든 영상의 전체 SHA-256을 계산하고, 200개 또는 전체 완료 때 DB에 반영했다. 174개 폴더는 전체 내용 검사가 끝나야 첫 저장이 일어났다. UI는 이후 썸네일 생성까지 기다렸다.
- 앱의 연결·자동 재검색·폴더 관리 경로에 메타데이터만 읽는 스캔을 적용했다. 목록을 먼저 갱신하고 썸네일은 별도로 생성한다. 진행 개수·중지·계속을 제공하고, 동일한 실패 파일을 한 세션에서 계속 재시도하지 않는다.
- 미검증 지문은 빈 값으로 보존하고 중복·이동 일치 판단에서 제외한다. 중복 비교를 열 때 같은 크기의 미검증 후보만 전체 검사한다. 파일 이동의 전체 내용 무결성 검사는 유지한다.
- 썸네일 작업 도중 사용자가 대표 이미지를 바꾸거나 파일 경로·수정 시각이 바뀌면 이전 작업이 새 상태를 덮어쓰지 않는다. 종료·잠금·업데이트·파일 이동에서는 백그라운드 추출을 중지한다.

## 검증

- `fast-index-final.log`: 관련 회귀 54개 통과, Mac 전용 1개 제외.
- `fast-index-analyze.log`: 정적 분석 오류 없음.
- `fast-folder-ui.log`: Windows 네이티브 UI 검사 통과. 173개 작은 비영상 시험 파일과 실제 영상 fixture 1개를 등록했다. 목록 174개가 403ms에 보였으며, 당시 썸네일 작업은 1/174였다. 중지 후 목록 유지·계속 버튼을 확인했다. OS 선택기 반환값만 대체했다.
- 첫 UI 검사에서 상태 갱신 콜백이 Future를 반환하는 오류를 발견해 수정한 뒤 재실행했다. 실패 로그는 `fast-folder-ui-first-failure.log`에 보존한다.
- 로그는 `build/verification/`, UI 근거는 `build/e2e/fast-folder.png`와 `fast-folder-time.txt`에 있다. 403ms는 debug 시험 자료 결과이며 사용자의 632GiB 폴더 전체 검사 속도로 해석하지 않는다.
- 카탈로그·잠금 DB의 일관된 사본을 사용자 앱 설치 경로의 별도 백업 폴더에 보존했다. 원본 영상은 수정하지 않았다.
- Release 빌드 성공. 현재 설치본 복사본에 수정한 `data/app.so`를 넣고 `--verify-install`을 실행했다. 잠금·DB·이동 무결성·메타데이터 교환·재생 이력·썸네일·NFO·실제 재생·최소화/복원 검사가 통과했다. 결과는 `build/verification/installed-candidate-result.json`에 있다.
- 설치된 Flutter 엔진·SQLite·libmpv·업데이트 설정과 빌드 산출물이 같은 해시임을 확인한 뒤, 기존 설치본의 `data/app.so`만 백업 후 교체했다. 설치 코드 SHA-256은 `6388a88b0dd5786740077ece054b71697d32b0fd2406743268077b0a9b416abd`다. 버전 표시와 공개 배포본은 0.2.0으로 유지한 로컬 수정본이다.
- 수정된 설치본 재시작과 기존 비밀번호 잠금 화면을 확인했다. 사용자에게 앱에서 직접 잠금을 해제하도록 요청했으며 인증을 우회하거나 비밀번호를 수집하지 않았다.

## Falcon v3.0.134 메뉴 검토

실행 중인 앱에서 관리 메뉴를 열어 확인했으며, 설치된 어셈블리의 리소스·IL을 읽어 처리 범위를 조사했다. 실제 파일·즐겨찾기 삭제는 실행하지 않았다.

| 메뉴 | 확인한 동작 | 검토 결과 |
| --- | --- | --- |
| 모든 썸네일 자동설정 | 현재 라이브러리에서 썸네일이 없는 파일을 조회해 생성한다. 기존 썸네일은 대상에서 빠진다. 시작 확인·진행률·중지 경로가 있다. | 유용하다. 이름은 ‘없는 썸네일 생성’이 정확하다. 목록 표시를 기다리게 하지 않고 대상·성공·실패 수를 보여주는 편이 좋다. |
| 휴지통 비우기 | 확인 후 앱 휴지통 파일에 `File.Delete`를 호출한다. 실패 항목과 중지 후 남은 항목은 유지한다. | 실제 영구 삭제다. 삭제 대상 수·용량·범위를 확인창에 표시하고 위험 작업으로 구분해야 한다. |
| 없는 파일의 즐겨찾기 정리 | 아카이브 경로 재연결을 먼저 시도한 뒤 DB의 파일 연결 여부와 실제 경로 존재를 검사한다. 파일 수·즐겨찾기 수·경로 일부를 제시하고 확인받아 삭제한다. | 재연결 우선은 좋다. 드라이브 연결 해제·접근 오류를 실제 삭제와 구분하지 못하면 기록 손실 위험이 있다. 연결 불가 상태는 보류하고 사용자가 대상을 고르게 하는 편이 안전하다. |

휴지통 메뉴를 여는 좌표 조작은 창 상태에 따라 삭제를 확정할 수 있다는 이유로 자동 승인 검토가 차단했다. 해당 조작을 우회하지 않고 리소스·IL 검토로 마무리했다.

## 범위와 한계

- 폴더의 빠른 스캔은 지문을 새로 만들지 않는다. 앱 밖에서 이동된 미검증 파일을 내용만으로 자동 연결하지 않으며, 기존 항목은 오프라인으로 보존하고 명시적인 파일 재연결을 사용할 수 있다. 앱 내부 이동은 ID·분류를 유지한다.
- Mac 실기, 공개 릴리즈 게시, Falcon 기능 변경은 이번 작업 범위에 포함하지 않는다.
