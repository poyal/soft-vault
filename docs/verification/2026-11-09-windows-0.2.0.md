# 0.2.0 Windows 로컬 후보 검증

실행 ID는 `pre-release-20261109-154747`, 후보 버전은 `0.2.0+2`이다. 현재 PC에서 가능한 검사만 수행하며 별도 Windows·Mac 실기 검사와 릴리즈 업로드는 사용자 요청에 따라 집에서 이어간다. 이전 `0.1.0`의 다른 장비 성공 결과를 이번 후보 결과로 사용하지 않는다.

## 출처와 환경

- Windows x64, OS build 26300, Intel i7-8700B. 기존 하드웨어 기록은 UHD 630·RAM 63.8GiB이며 해당 기록의 시각은 2026-11-08이다.
- Flutter `3.47.9`, Dart `3.13.7`, Visual Studio 2022 BuildTools. SDK 원본 버전 정보와 이번 실행의 OS·CPU·lock 파일 해시는 실행 폴더의 `flutter-version.json`, `environment.json`에 보존한다.
- 시작 기준 커밋은 `230e2bb`이며 이전 작업의 업데이트·설정·필터·종료·재생 기록·AI 교환 변경을 포함한 작업 트리에서 검증을 시작했다. 검사 중 발견한 문제를 수정하고 영향받는 검사와 전체 일반 회귀를 다시 실행했다. 처음부터 끝까지 변경 없는 한 번의 실행이었다고 주장하지 않는다.
- 최종 소스 지문은 `1f0ebd7c7db6b65f19d796de8978fb6632fe4d91d6f07b6049e51a5a3c979ea7`이다. `source-final-before.json`과 `source-final-after.json`으로 파일별 SHA-256을 대조한다. LF 정규화하며 앱·테스트·검증 도구·플랫폼·공개 업데이트 설정을 포함한다. 문서·빌드 생성물·개인키는 제외한다.
- 원시 근거는 `build/runs/pre-release-20261109-154747/`에 보존한다. fixture는 `.tools/fixtures/trailer.mp4` 및 `codecs/`의 자막 포함 11개 영상이며 해시는 `fixture-hashes.json`에 있다. 사용자의 라이브러리 대신 임시 DB와 복사한 시험 영상을 사용했다.

## 추가한 검사와 수정

- AI 정보 교환: 백업 실패 시 원본·요청 보존, 잘못된 필드·다른 요청 거부, 빈 라이브러리·2천 건 동일 파일명의 ID 구분, 실제 클립보드·파일 입출력·취소·요청 보존·선택 적용.
- 업데이트: 로컬 HTTP fixture로 서명 확인→손상 다운로드 거부→재시도→설정 저장을 검사한다. 실제 네트워크·게시 서버에 의존하지 않는다. 같은 크기로 변조된 파일도 해시로 거부한다.
- 목록·카드: 숫자 제거, 재생 상태 아이콘, 체크박스 위치, 즉시 선택·연속 클릭 시 재생 방지와 행 더블클릭 재생을 검사한다. 체크박스를 행의 더블클릭 인식 영역 밖으로 옮겨 지연과 의도하지 않은 재생을 수정했다.
- 사생활 보호: 비밀번호 표시 체크박스에 Material 그리기 영역을 제공해 설정 카드 안에서 발생하던 Flutter assertion을 수정했다.
- 설정 전용 화면으로 변경된 후 남아 있던 네이티브 검사 조건을 갱신했다. 백그라운드 분석이 갱신하는 영상 전체 필드 대신 선택 ID를 비교하도록 검사 조건을 바로잡았다.
- Windows 전체 검증에 신규 profile 검사와 종료·업데이트 검사를 연결했다. 필수 profile·종료 결과가 누락되면 보고서를 성공 처리하지 않는다. 설치 검사는 실행별 고유 결과 파일과 실제 실행 파일 경로를 확인한다.
- manifest 생성은 검증된 플랫폼을 명시해야 한다. 이전 Mac ZIP이 남았다는 이유로 새 Windows 후보 manifest에 자동 포함하지 않는다.

최초 실패 로그는 실행 폴더의 `*-before-*-fix.log`에 보존한다. 이전 전체 결과는 `previous-verification`, `previous-e2e`, 이전 Windows ZIP은 `previous-package`에 보존했다. 사용자 변경을 reset하거나 원본을 삭제하지 않았다.

## 측정과 제한

- 종료 요청부터 실제 프로세스 종료까지 18회 **170.884~330.208ms**, 평균 244.645ms. 대기·재생·일시정지 × 일반·연속 닫기 × 각 3회이다. profile probe가 앱의 정상 종료 경로를 실행하며 최종 설치 ZIP의 외부 UI 자동화와는 구분한다.
- 1만 파일: 최초 스캔 13,109ms, 재검색 1,864ms, 검색 p95 10.027ms, 1천 건 수정 1,289ms, 복원 2,073ms. 실제 동영상 1만 개를 동시에 디코딩한 부하는 아니다.
- 5만 건 합성 카탈로그: 검색 p95 47.753ms, 목록 334ms, 컬렉션 312ms, 중복 조회 350ms. 해당 테스트의 예산을 모두 충족했다.
- 창 크기 변경은 7개 화면 × 3회이며 화면별 raster p95 회차 평균은 약 17.6~20.2ms였다. 재생 중은 16.195/20.787/16.430ms, 일시정지는 20.483/18.569/19.919ms였다. 모든 구간이 60fps 예산 이내인 것은 아니다. 최종 체크박스 이벤트 영역 수정 이전의 측정이며 실제 드래그·다른 GPU·배율과 동일하다고 해석하지 않는다.
- 자동 UI는 OS 파일 선택기를 대체하고 컨트롤러/테스트 이벤트로 입력한다. 실제 한글 IME, 깨끗한 계정 첫 실행 경고, 구 배포본→후보의 전체 교체, 물리 HDR·스피커, 장시간 재생·외장 드라이브 분리, Mac 도우미 교체는 아직 확인하지 않았다.
- 보고서의 기존 CPU/GPU 자원 표와 1천 파일 이전/이후 표는 과거 참고 자료이며 현재 후보의 새 측정으로 합산하지 않는다.
