## 발견한 문제와 수정

1. 기존 네이티브 검사가 한 번 클릭으로 재생하던 동작, 제거된 평점 버튼, 이전 사이드바 폭 등을 가정했다. 현재 UI의 선택/더블클릭·메뉴·평점 드롭다운과 주기적 재생 위치 저장에 맞춰 수정하고 관련 검사를 다시 실행했다. 잘못 추가했던 중복 검색 버튼은 제거했고 기존 검색 버튼의 단축키 안내만 남겼다.
2. 스크린샷에서 재생 단축키 키캡이 각각 전체 너비로 늘어나 영상 영역을 가리는 문제를 발견했다. KeyCap의 크기를 내용에 맞추고 Wrap 안에서의 크기를 검증하는 회귀 테스트를 추가했다. 양쪽 OS 재캡처에서 수정 결과를 확인했다.
3. Windows 연속 재생 실패를 처음에는 움직이는 행의 더블클릭 좌표 문제로 추정했다. 좌표를 고정해도 전체 검사에서 다시 실패했고, 재생 콜백을 직접 호출해 입력과 분리한 검사에서도 재현됐다. 비동기 파일 조회·이전 위치 저장이 끝나는 순서에 따라 native 재생 큐에 들어가는 순서가 바뀌는 앱 결함이었다. d4118bb에서 준비 단계부터 재생·선택 상태 갱신까지 같은 큐에 넣도록 수정했다. 초기 추정과 실패 로그를 보존한다.
4. Mac의 중간 실행 래퍼 2회는 테스트·화면 수정 전 소스 지문을 고정해 두어 마지막 지문 비교에서 실패했다. 이를 기능 통과로 덮어쓰지 않았다. 중간 로그를 보존하고 최종 소스로 관련 검사·Release·패키징·설치 진단을 새로 실행했다.

이번 실행에서 통과한 변경 영향이 없는 검사와 수정 후 재실행한 검사를 결합한다. 모든 검사를 매번 새로 실행했다는 의미는 아니다. 최종 재생 변경 후 양쪽에서 분석·일반 회귀·앱 재생·확장 기능·네이티브 부하·UI 반응성·redesign·종료·Release·설치 검증을 다시 수행했다. 화면 검수 범위와 증거는 [스크린샷 검수](SCREENSHOT-REVIEW.md)에 기록한다.

Windows Flutter AXTree 접근성 경고는 로그에 보존한다. 기능·화면 검사가 통과해도 스크린리더 동작을 검증한 것은 아니다. 설정 화면 검사용 fixture가 표시하는 0.1.0+1은 테스트에서 주입한 값이며 실제 배포 버전은 패키지 설정과 서명 manifest에서 별도로 검증한다.

## 제한과 정리

실제 사용자 카탈로그 전체의 구 배포본→후보 업그레이드, 물리 HDR·스피커 출력, 수시간 재생, 깨끗한 OS 첫 실행 경고는 NOT_RUN이다. 자동 설치·업데이트 도우미 검사와 이 범위를 구분한다. Windows 코드 서명과 Apple Developer ID 서명·공증은 없다. Mac 번들은 로컬 무결성 서명을 사용한다.

테스트 앱 종료, Mac LaunchAgent 2개 제거·DMG 마운트 해제, Windows 설치 등록 제거·SQLite 복구를 확인했다.
