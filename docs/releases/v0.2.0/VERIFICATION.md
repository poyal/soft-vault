# 0.2.0 두 PC 릴리즈 후보 검증

실행 ID는 `release-020-20261109-173203`, 버전은 `0.2.0+2`이다. 2026-11-09 사용자의 두 PC 접속·릴리즈 절차 요청에 따라 별도 Windows와 Mac에서 검증했다. 앞선 [개발 PC 기록](../../verification/2026-11-09-windows-0.2.0.md)과 구분한다. 보류했던 Windows 클립보드 검사도 같은 소스로 다시 실행해 통과했으며, 두 플랫폼의 필수 자동 검사와 설치 검증을 완료했다.

## 소스와 환경

- 최종 검사 코드 커밋: `281af5c0ad4f5259c2ecff7afac0dbd14a477d24`. 앱 코드·플랫폼·의존성은 로컬 후보 `4f1add9`와 같으며, 후속 커밋은 Mac 업데이트·종료 검사와 네이티브 검사 보완이다.
- 양쪽 검증·빌드 시 소스 지문: `ad22e6ee8ccde5a5270ef2229e213504e4cab1edb3b15fbe7c7012c6fe4ddb8a`. 초기 원격 지문 `0d070dcee24f266eb51f3785ae170b44a696e4acf13662df575011bc324bf837` 이후 변경 파일은 `integration_test/support/native_surface.dart`, `integration_test/metadata_exchange_flow_test.dart`뿐이다. 영향받는 검사를 다시 실행하고 실행별 지문과 실패 로그를 보존했다.
- 검사 후 `8ff99c6`에서 `tool/update_helper_smoke.dart`의 cascade 두 줄을 포매터 형식에 맞춰 한 줄로 합쳤다. 공백을 제외한 내용은 같고 앱·도우미 실행 코드는 바뀌지 않았다. 이 형식 정리 후 로컬 지문은 `4972fe9a41ec6defd5739c36ed574c8a40c5b81f97f044ec29b7f1ccdd2e66ac`이며 실제 원격 검사 지문과 구분한다. 이후 문서 변경은 지문에서 제외된다.
- Windows 11 Pro build 26300, Ryzen 7 9700X, RTX 4070 Ti, RAM 약 31.7GiB. NVIDIA 드라이버 `32.0.16.1714`, DisplayLink 연결 포함.
- Mac mini Apple M4, macOS 27.0.1 / 26A434, arm64, RAM 16GiB.
- Flutter 3.47.9 / Dart 3.13.7와 고정 lock 파일을 사용했다. 원격 PC의 이전 검증 SDK·미디어 도구를 재사용하고 소스·빌드·DB·fixture는 새 작업 폴더에 격리했다.
- 원시 근거와 후보 파일은 로컬 `build/release-020-20261109-173203/`에 있다. 개인 라이브러리 대신 임시 DB와 시험 영상을 사용했다. 서명 개인키는 전송하지 않았다.

## 발견한 문제와 조치

- Windows의 긴 원격 작업 경로 때문에 MSBuild 종속 프로젝트가 260자 경로 제한에 걸렸다. 전역 OS 설정을 바꾸지 않고 짧은 격리 폴더에서 재개했다.
- Mac의 첫 네이티브 창이 `hidden` 상태로 시작해 첫 프레임을 기다렸다. 검사 보조 함수에서 실제 창을 표시·활성화하고 프레임 생성 가능 여부·표시·최소화 상태를 최대 10초 확인한다. 테스트 사이에는 lifecycle 값이 null로 초기화될 수 있어 `resumed` 이벤트 자체를 강제하지 않는다. 가짜 프레임이나 물리 캔버스로 우회하지 않는다.
- AI 정보 교환 검사가 기존 클립보드를 보관하다 실패하면 정리가 실행되지 않던 부분을 보완했다. 검사 도구의 클립보드 접근만 짧게 재시도하며, 앱의 복사·붙여넣기 버튼은 실제 OS API로 검증한다.
- 별도 Windows에서는 Flutter와 독립 Win32 `OpenClipboard` 검사 모두 오류 5를 반환했다. 세션 1의 `WinSta0\\Default`와 기본 입력 바탕화면 접근은 확인됐지만, 읽을 수 있는 클립보드 점유 창·소유 프로세스는 확인되지 않았다. 잠금 화면 때문이라고 확정하지 않는다. 일반 셸을 통한 실행에서도 동일했고, 보안 설정이나 다른 사용자 프로세스를 변경하지 않았다. 이 검사는 건너뛰어 통과 처리하지 않는다.
- 사용자의 후속 검사·게시 요청 후 같은 Windows 소스와 실제 클립보드로 다시 실행해 전체 내보내기, 붙여넣기, 파일 입출력, 취소, 요청 보존, 선택 적용이 통과했다. 전체 보고서 생성과 검사 후 소스 지문 대조도 통과했다. 과거 오류의 근본 원인은 확정하지 않았으며 원래 실패 로그를 보존했다.
- Mac 원격 래퍼는 모든 검사와 설치 성공 후 마지막 Python heredoc의 CRLF 때문에 비정상 종료했다. 원래 실패 로그를 보존하고 각 필수 suite의 성공 종료, 18개 종료 결과, 업데이트 5개, 설치 결과, 최종 소스 지문을 별도 검증해 `reconciled-status.json`에 기록했다. 이를 제품 오류로 해석하거나 래퍼 실패만 무시해 통과로 처리하지 않았다.

## 게시 결과

- [Soft Vault 0.2.0](https://github.com/poyal/soft-vault/releases/tag/v0.2.0)을 `2026-11-09T10:27:22Z`(한국 시간 19:27)에 정식 공개했다. 최신 안정 릴리즈이며 draft·prerelease가 아니다.
- 태그 `v0.2.0`은 `bb1192ec9272a0200edcaa93a0002fa3b192de2d`를 가리킨다. 빌드 기준 이후 변경은 앞서 기록한 검사 파일 형식 정리와 문서이며, 태그를 이동하지 않았다.
- ZIP 2개, 각 `.sha256`, `update.json`, `update.json.sig`의 6개 자산을 업로드했다. 초안 다운로드를 먼저 대조한 뒤 공개했고, 공개 URL에서 인증 없이 재다운로드해 모든 크기·SHA-256이 고정 후보와 일치함을 `2026-11-09T10:27:30Z`에 확인했다.
- 게시 원본 메타데이터와 재다운로드 대조 결과는 실행 폴더의 `published-release.json`, `publication-verification.json`에 보존했다. 개인키는 로컬에 유지하고 공개 자산에 포함하지 않았다.

임시 Scheduled Task와 Mac LaunchAgent·절전 방지 프로세스를 해제했고, 이 실행이 만든 앱 프로세스가 남지 않았음을 확인했다. Windows 개발 SQLite DLL도 복원됐다. 원시 실패 로그·후보·사용자 데이터·기존 개발 도구는 보존했다.

## 남은 범위

필수 자동 검사·정식 게시·공개 파일 재다운로드 해시 확인을 완료했다.

실제 한글 IME·OS 파일 선택기·물리 HDR/스피커·수시간 재생·구 배포본 전체 교체·깨끗한 계정의 첫 실행 경고는 자동 검사가 대신하지 않는다. Windows 코드 서명과 Apple Developer ID 서명·공증은 제공하지 않는다. 앱 업데이트 manifest의 Ed25519 서명은 이 OS 서명들과 별개다.
