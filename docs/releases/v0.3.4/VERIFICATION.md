## 설치된 Release의 장시간 재생

### 4K60 렌더 드롭과 구버전 비교

이번 설치 진단 표면에서는 큰 렌더 드롭을 관측했습니다. 첫 장시간 실행을 중단·보존하고 이전 `0.3.3` 소스(`7108c28`)에 같은 선택 진단만 추가해 플랫폼별로 구버전과 후보를 각각 60초씩 순차 실행했습니다. Mac의 비활성 창을 활성화해도 증가 양상은 해소되지 않았고, 화면 절전은 꺼져 있었습니다.

## 검수·실행기 문제와 재개

- Windows 1280×800·1440×900의 이번 재생 캡처와 목록 화면을 확인했습니다. 타임라인과 조작부의 잘림·겹침은 보이지 않았습니다. 자동 네이티브 UI 검사와 사람이 물리 장치로 조작한 검수는 구분합니다.
- Git 작성자 미설정으로 최초 후보 커밋이 실패해 기존 기록과 같은 `Codex <codex@localhost>`를 명령 범위에서 지정했습니다. Mac 최초 아카이브는 검사를 시작하기 전에 올바른 후보로 교체했습니다.
- Windows 실행기가 Dart의 stderr 진행 메시지를 오류로 처리했습니다. 종료 코드를 기준으로 판단하도록 실행기를 수정하고 재실행했습니다. 실패 로그를 보존했으며 제품 코드의 실패로 집계하지 않습니다.
- Mac 최초 기능 검사는 설치 진단 추가 전 소스 지문 `8082b9bed881dda4e9cb2711901219a64d002dfbba37c897e40a3c9733d175f9`에서 수행했습니다. 최종 후보와의 차이가 `lib/install_check.dart`, `lib/install_soak.dart` 두 진단 파일뿐임을 파일별 해시로 대조했습니다. 최종 정적 분석·일반 회귀·Release 빌드·설치·장시간 검사는 새 소스로 수행했습니다.
- Mac 최초 실행기의 HTTPS 테스트 파일명이 잘못되어 해당 단계에서 중단됐습니다. 이미 통과한 기능 결과를 보존하고 실제 네트워크 테스트 경로로 재실행했습니다. 검사 조건은 완화하지 않았습니다.
- Windows 구버전 비교 빌드가 OS 경로 길이 제한에 걸려 짧은 임시 경로에서 다시 빌드했습니다. 비교 실행기의 종료 코드 수집은 프로세스 핸들을 유지하도록 수정했고, 두 비교를 다시 실행해 실제 종료 코드 0과 진단 성공을 함께 확인했습니다. Windows 최종 검사 실행기의 외부 PowerShell 래퍼도 Dart의 stderr 진행 메시지 때문에 비정상 종료 상태를 표시했지만 내부 단계별 종료 코드 검사·완료 마커·원시 결과를 별도 감사로 대조했습니다.

## 배포와 제한

검증된 파일 8개의 이름·크기·SHA-256은 [파일 고정값](release-assets.json)에 있습니다. EXE·DMG와 각 체크섬, 두 `.svupdate`, `update.json`, `update.json.sig`만 게시합니다. 내부 ZIP은 게시하지 않습니다. 업데이트 payload가 설치 검증 ZIP과 같은 바이트이며 기존 공개키로 Ed25519 서명이 검증됐습니다. [서명 기록](signing-verification.json)을 보존합니다.

기존 사용자 라이브러리 전체 업그레이드, 물리 HDR·스피커 출력, 깨끗한 OS의 첫 실행 경고, 전체 UI를 포함한 수 시간 재생은 별도 검증 대상입니다. Windows 코드 서명과 Apple Developer ID 서명·공증은 제공하지 않습니다. 자동 업데이트 서명은 OS 코드 서명과 별개입니다.

최종 판정: **후보 검증·서명 PASS, 게시 전**.
