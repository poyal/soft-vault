# 0.1.0 두 OS 검증 기록

검증일: 2026-11-09 KST. 실제 Windows PC와 Mac mini M4에서 수행했다. 이전 개발 PC의 누적 결과를 이번 합계에 넣지 않았다.

- 앱 코드 기준: `ca353a8ce571ca20891364c885f0b84b50f3e838`. Windows Release와 ZIP은 이 소스에서 만들었다.
- 최종 검사 코드: `def5b1f40145c2e9e777bbcfa8bbf9054f476fdf`. Mac Release는 이 기준이다. 이후 변경은 문서뿐이다.
- 두 기준의 지문 목록을 대조하면 변경 파일은 `integration_test/stress_flow_test.dart`와 `test/stress_scenarios_test.dart`뿐이다. 앱·플랫폼·의존성·패키징 코드는 같다. 변경한 검사만 두 OS에서 다시 실행했다.
- 두 PC 최종 소스 지문: `2599bbd6d9668ec728df5168a126dfab65da281a0d330088852f1b954d5c4120`.
- Windows 최초 전체 실행의 검사 전·후 지문: `09238b078809bc0f88ce3a6dcbef95999e7935256c50fb6ad85b54b84cd701ca`. 위 두 검사 파일이 바뀌기 전 값이다.
- Flutter 3.47.9 / Dart 3.13.7, Flutter Git `c197ca5199e9ee5661e865596c9c07294dfab51c`, 의존성 lock 사용. Windows VS 2022 BuildTools, Mac Xcode 27.2 / CocoaPods 1.17.0.

## 디자인과 실제 창

1280×800·1440×900 주요 화면, 작은 실제 창, 최대화, 실제 전체화면과 복원을 확인했다. 네이티브 크기·DPI·제출 프레임의 일치와 가장자리 배치를 검사하며 테스트용 가짜 물리 캔버스를 사용하지 않는다. 양쪽 최신 목록·설정·재생 캡처를 육안 검토했다. 영상 안 비율 여백은 허용하고 앱·사이드바 바깥 레터박스는 결함으로 다뤘다.

Windows 시안 대비 전체 이미지 평균 RGB 오차는 1280px에서 4.555/255, 1440px에서 4.368/255였다. 미리보기 영역 평균 오차는 각각 1.291, 1.381이었다. 최신 사용자 지정에 따른 설정·배우/태그·영상 전용 UI 차이와 플랫폼 글꼴·안티앨리어싱 차이가 포함된다. 이 수치는 픽셀 완전 일치 판정이 아니다. 매뉴얼의 9장 캡처는 [출처 기록](../../screenshots/README.md)을 따른다.

## 성능과 스트레스

다른 기기의 단일 실행 수치를 개선 배수로 비교하지 않는다. 파일 부하는 작은 고유 파일, 카탈로그 부하는 합성 행을 사용하며 대량 영상 동시 디코딩이 아니다.

Windows profile 스트레스 중 30.2초·15표본에서 앱 CPU 평균 1.34%, 최고 7.5%, GPU 최고 엔진 3%, private working set 최고 232.6MiB, GPU 공유 메모리 최고 26.3MiB였다. 시스템 CPU 평균 4.8%, 가용 RAM 최저 21.1GiB였다. CPU는 전체 논리 프로세서로 정규화했고 GPU 엔진 사용률을 서로 합산하지 않았다. 이 표본에서 자원 포화는 보이지 않았다. Mac GPU 사용률은 수집하지 않았다.

스트레스는 영상 전환 40회, 전체화면·최소화·복원 12회, 1만 행 80회 스크롤, 편집 200회·이동 96회, 동시 스캔·백업, 64MiB 검증 복사·취소·디스크 부족 주입·별도 프로세스 종료 복구를 포함한다. 수시간 soak나 물리 디스크 분리 시험은 아니다.

## 설치 파일과 실행

파일 크기·SHA-256은 [배포 안내](README.md)에 기록했다. Windows ZIP의 파일 해시 43개를 대조했고, 개발 도구 없는 PATH와 개발 SQLite DLL 격리 상태에서 설치 사본을 실행했다. Mac ZIP은 새 폴더에 풀어 manifest·`codesign --verify --deep --strict`를 검사하고 최소 PATH에서 실행했다. 이후 같은 설치 앱을 `open -n -W`로 새로 실행해 LaunchServices 경로도 통과했다.

양쪽 설치 사본에서 임시 DB, 비밀번호, 원본 해시 검증 이동, 썸네일·미리보기, 이어보기·장면·컬렉션·규칙·NFO, 최소화/복원과 11종 코덱을 확인했다. 설치 진단과 소스 UI E2E는 별도 범위다. 전체 UI E2E가 배포 ZIP 안에서 실행됐다고 해석하지 않는다.

## 발견한 문제와 제한

- Mac 플러그인 연결에 CocoaPods 구성을 추가했고, 별칭 경로를 정규화해 중복·연결 해제·이동 판정 오류를 수정했다.
- Windows 최대화 복귀 시 전체화면 종료 이벤트 누락을 실제 창 상태로 보완했다. Mac 전환 완료 전 다음 전환이 겹치던 문제는 요청 직렬화로 수정했다.
- Mac 최소화 복원은 일반 창인데 Windows식 기대값을 쓰던 스트레스 검사와 `dart.exe` 고정 경로를 수정했다. 실패 로그를 보존하고 해당 검사를 양쪽에서 다시 통과시켰다. 상한을 올리거나 실패 항목을 제외하지 않았다.
- Mac Flutter 도구의 초기 전면 표시 경고(`open returned 1`)가 있었다. 이미 실행 중인 앱의 `open`과 최종 설치 앱의 새 LaunchServices 실행은 종료 코드 0으로 통과했다. profile 전체화면 반복 중 `Resize timed out` 경고 2회가 기록됐으며 반복 완료·복원·프레임 검사는 통과했다.
- Windows는 unsigned, Mac은 ad-hoc 서명이며 Apple 공증이 없다. 다운로드 격리 속성이 붙은 깨끗한 계정의 첫 실행 경고는 검사하지 않았다.
- 4K HEVC 10bit·BT.2020/PQ 디코딩은 확인했으나 물리 HDR 출력·색 정확도·스피커 소리는 검증하지 않았다. 파일 선택창은 대체했고 입력은 컨트롤러/키 이벤트로 검사해 OS 선택창·IME 실기는 포함하지 않는다.
- 이전 공개 배포본이 없어 설치본 간 업그레이드는 N/A다. DB 스키마 이전·백업 복원은 서비스 검사 범위에 포함했다.

## 근거와 정리

실행 명령은 `scripts/verify-windows.ps1`, `scripts/verify-macos.sh`의 단계와 두 OS의 `package-*`·`verify-install-*`를 사용했다. Mac은 발견한 문제를 고친 단계부터 계속 실행했다. 마지막 두 테스트 파일 변경 후에는 영향받는 스트레스만 다시 검사했다. 결과 JSON은 [results.json](results.json)에 보존하며 원시 로그·실행별 실패 자료·캡처는 작업 공간 `build/release-work/{windows-evidence,macos-evidence}/`에 보관한다.

Windows 임시 예약 작업과 Mac 임시 launchd 작업은 남아 있지 않고 시험 앱 프로세스도 종료됐다. 소유한 Mac 절전 방지 프로세스를 종료했으며 개발 SQLite DLL 복원과 격리용 hold 파일 부재를 확인했다. SDK·SSH 전역 설정·검증 ZIP·사용자 자료는 보존했다.
